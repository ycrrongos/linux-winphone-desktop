# Screen power and hooks (2026-11-13)

“模式与个性化 → 屏幕与壁纸”提供桌面/Start/锁屏共用图片、自动熄屏开关、
30秒至60分钟的常用超时，以及独立的亮屏/熄屏命令。手机还可选择把搜索键换成
任务列表；长按返回仍保留任务列表。

自动熄屏读取 Denial 的真实 input_idle_ms / idle_inhibited，因此应用内触摸、
鼠标/键盘输入和阻止闲置的应用也参与计算。动画结束后才请求 native DPMS；
解锁仍只由原生 PAM 成功结果决定。普通桌面预览不会查询/改变宿主电源状态或
执行亮灭屏命令。

锁屏的亮屏时间轴为0–400ms自下而上显示壁纸、200–600ms时钟/日期下落，
共享 WP 非线性曲线，熄屏反向。Start 熄屏复用已保存的磁贴关闭样式，并用实际
Start 动画时长控制变黑；真实解锁后重播保存的 Start 进入样式。减少动画设置
会令电源切换即时完成。

## Privileged hooks

运行安装脚本会把 `packaging/win10x-screen-hooks` 安装到 root 所有的
`/usr/local/libexec/win10x-screen-hooks`；这一步不在普通预览时执行。
设置页“授权当前亮灭屏命令…”通过 pkexec 正常授权，将这两条命令快照保存到
root 600 文件 `/etc/win10x/screen-hooks/UID.json`，只为该用户添加固定 helper
的 `off`、`on` 两个 sudoers 项（440，先通过 visudo 检查）。

后续执行使用 `sudo -n`，没有 `NOPASSWD: ALL`。修改命令、关闭管理员模式时，
运行阶段会检查当前配置与授权快照是否一致，不一致则拒绝执行，必须重新授权。
普通模式以用户身份执行 `/bin/sh -c`；两种模式均有15秒执行预算和终止处理。
日志只记录阶段/退出码，不打印命令、输出或凭据。

## Verification boundary

本轮用户说明手机不连接：只在本地分析、单元测试、隔离文件系统 helper 测试和
真实 Flutter 预览中验证。原生 DPMS/物理电源键和真实管理员授权仍需手机验收。
固定 Denial 二进制只有启用原生 ambient-display 的设备提供关屏前握手；自动
熄屏始终由本实现等待动画再请求 DPMS。没有这个原生握手的电源键关屏会由
powered 状态观测执行命令、准备下次亮屏画面，但不能保证关屏前完整播放动画。
这项限制需要后续原生协议支持，不能把预览动画当物理按键验收。

壁纸选择器是外壳内的文件浏览页：可进入主目录、系统图片目录、上一级，也可直接
输入目录/图片路径。先尝试解码图片（文件上限64MB），成功才更新已保存选择；
取消、目录无权限或解码失败均保留原壁纸，不要求安装额外的文件对话框程序。
